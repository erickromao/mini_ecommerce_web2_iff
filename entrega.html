II

Tecnologias Utilizadas

O projeto foi desenvolvido com tecnologias modernas do ecossistema JavaScript/TypeScript, adotando uma arquitetura full-stack unificada por meio do framework Next.js, que centraliza tanto o front-end quanto as rotas de API no mesmo repositório.

Camada Tecnologia / Biblioteca Finalidade
Front-end Next.js 16.1.7  ·  React 19.2  ·  TypeScript 5 Framework full-stack com App Router, Server Components e Client Components
Estilização Tailwind CSS 4 Estilização utilitária responsiva e sistema de design indigo/violet
Back-end Next.js Route Handlers  ·  Node.js API REST com endpoints organizados por recurso (products, users, auth)
Autenticação jose (JWT)  ·  bcryptjs Tokens JWT em cookies httpOnly com validade de 7 dias; hash seguro de senhas
Banco de dados Neon (PostgreSQL)  ·  @neondatabase/serverless PostgreSQL serverless com driver optimizado para ambientes edge e Lambda
Qualidade de código ESLint 9  ·  TypeScript strict Análise estática, linting e tipagem forte em todo o projeto
Versionamento Git  ·  GitHub Controle de versão com 25 commits seguindo a convenção Conventional Commits
Deploy Vercel Deploy automático via integração GitHub com CI/CD, CDN global e HTTPS
III

Funcionalidades Implementadas

O sistema consiste em um painel administrativo completo para gerenciamento de produtos e usuários de um mini e-commerce. Todas as funcionalidades obrigatórias foram implementadas, acompanhadas de recursos adicionais que ampliam a segurança e a usabilidade da aplicação.

Funcionalidades Obrigatórias
  • CRUD de Produtos — criação, listagem, edição e exclusão
  • CRUD de Usuários — criação, listagem, edição e exclusão
  • API REST — Route Handlers do Next.js, padrão RESTful
  • Banco de dados — PostgreSQL via Neon, serverless
  • Versionamento Git — 25 commits com histórico estruturado
  • Deploy em produção — Vercel com HTTPS e CDN global
Funcionalidades Bônus
  • Autenticação JWT — login com cookie httpOnly (7 dias)
  • Middleware de proteção — todas as rotas verificadas
  • Autorização por perfil — admin (total) e usuário (leitura)
  • Busca e filtros — nome, categoria e status no servidor
  • Paginação server-side — 8 itens por página
  • Upload de imagem — foto do produto em base64
  • Dashboard — estatísticas dinâmicas em tempo real
  • Seed automático — dados iniciais gerados no primeiro acesso
IV

Arquitetura e Rotas da API

O projeto segue a estrutura de diretórios do App Router do Next.js, onde as pastas dentro de app/api/ definem automaticamente as rotas da API REST, e as demais pastas correspondem às páginas da interface.

// Estrutura de pastas do projeto (simplificada) mini_ecommerce_web2_iff/ ├── src/ │ ├── app/ │ │ ├── api/ ← Route Handlers (back-end) │ │ │ ├── auth/ │ │ │ │ ├── login/route.ts ← POST autenticação │ │ │ │ ├── logout/route.ts ← POST encerrar sessão │ │ │ │ └── me/route.ts ← GET sessão ativa │ │ │ ├── products/ │ │ │ │ ├── route.ts ← GET / POST │ │ │ │ └── [id]/route.ts ← GET / PUT / DELETE │ │ │ └── users/ │ │ │ ├── route.ts ← GET / POST (admin) │ │ │ └── [id]/route.ts ← GET / PUT / DELETE │ │ ├── login/page.tsx ← Tela de login │ │ ├── products/ ← Listagem, detalhe, new, edit │ │ ├── users/ ← Listagem, detalhe, new, edit │ │ └── page.tsx ← Dashboard principal │ ├── components/ ← Sidebar, Forms, Pagination… │ ├── context/AuthContext.tsx ← Gerenciamento de sessão │ └── lib/ │ ├── auth.ts ← JWT sign / verify │ ├── db.ts ← Conexão Neon + seed │ └── types.ts ← Interfaces TypeScript └── middleware.ts ← Proteção global de rotas

Endpoints da API REST

Método Endpoint Descrição Acesso
POST /api/auth/login Autenticação — gera JWT em cookie httpOnly Público
POST /api/auth/logout Encerramento de sessão — remove o cookie Autenticado
GET /api/auth/me Retorna dados do usuário logado Autenticado
GET /api/products Lista produtos com busca, filtro e paginação Autenticado
POST /api/products Cria novo produto Admin
GET /api/products/[id] Retorna produto por identificador Autenticado
PUT /api/products/[id] Atualiza dados do produto Admin
DEL /api/products/[id] Remove produto do sistema Admin
GET /api/users Lista usuários com busca e paginação Admin
POST /api/users Cria novo usuário com hash de senha Admin
GET /api/users/[id] Retorna usuário por identificador Admin
PUT /api/users/[id] Atualiza dados do usuário Admin
DEL /api/users/[id] Remove usuário do sistema Admin
